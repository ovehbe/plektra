# Quick Launcher open/close investigation

Code references below are to the unfixed branch tip (`0e710835`).

| Candidate | Evidence |
| --- | --- |
| A second open request is interpreted as a close | `QuickLauncherOpener.kt:14–29` sends a toggle for Plektra (also the Niagara fallback). `LauncherShortcutController.kt:93–97, 119–153, 282–293` routes assigned and power shortcuts there. IME editable-field SYM/Alt calls are initial-down only (`PhysicalKeyboardInputMethodService.kt:5378–5414`); the SYM, Alt and launcher-package paths in `InputEventRouter.kt:167–210` can call the shortcut again on a repeat if the IME still sees it. The Clicks direct action also uses the same opener (`ClicksButtonDirectAction.kt:27–30`); its mapper filters repeats and debounces by source/device (`ClicksButtonMappingCore.kt:75–86`), not across caller instances or sources. With `NEW_TASK`/`CLEAR_TOP` (`QuickLauncherActivity.kt:878–897`) and manifest `singleTop` (`AndroidManifest.xml:276–283`), a second request can reach `onNewIntent` rather than `onCreate`; only the former interprets the extra as a dismiss (`QuickLauncherActivity.kt:234–239`). The internal command uses an open-only intent (`CommandExecutor.kt:85–92`). |
| Trigger key crosses the focus handoff | Activity-level remapping and dispatch run before the search field (`QuickLauncherActivity.kt:253–301, 340–347`). A SYM shortcut, Back, or Escape only dismisses after a non-repeat down seen by the launcher and a matching uncanceled up (`:365–368, 659–670, 730–743`). But Enter/DPAD Center accepts a repeat down (`:397–404, 473–482`) or an unpaired up (`:673–682`). For example, SYM+Enter can open the launcher; releasing SYM first means Enter-up is no longer recognized as the shortcut and can launch the top result. A successful command finishes at `:720–726`. |
| Focus, lifecycle and timers | The Activity has no custom pause, stop, focus, or user-leave dismissal; `LocalizedComponentActivity.kt:6–10` only localizes the context. The window requests an initially hidden IME (`QuickLauncherActivity.kt:149–158`); IME finish/hide callbacks reset input/modifier state without finishing the Activity (`PhysicalKeyboardInputMethodService.kt:4207–4272, 4760–4775`). Manifest/intent no-history can remove the Activity when Android navigates away; that is distinct from a transient focus callback. The power-shortcut timeout resets its own mode, not the launcher (`LauncherShortcutController.kt:223–245`). The launcher animation timer only finishes after a dismiss request (`QuickLauncherActivity.kt:745–753, 932–940`). |
| Other close paths and settings | Background/close-button taps explicitly request dismissal (`QuickLauncherActivity.kt:185–215, 1105`); a context-menu dismiss hides the menu (`:1317–1319`). Confirming a command or matching a single result with auto-start and a nonblank query can finish the Activity (`:699–726`). Corner radius changes the sheet shape (`:945, 992–1001`), not dismissal. |

The unfixed Robolectric matrix ran 162 cases (27 sequences × 3 lifecycle orders × 2 settings profiles). It reproduced 72 unintended closes: 36 from second open requests and 36 from Enter releases or repeats. The other 90 cases, including deliberate dismissals, passed.

Robolectric can replay intent and key delivery sequences, but cannot establish which sequence the Q25 actually delivered without a device trace, or reproduce Android's real task/window-manager timing.
